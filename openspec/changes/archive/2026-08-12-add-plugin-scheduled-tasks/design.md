## Context

江湖面板已有常驻的 `/www/server/jh-panel/task.py` 进程，用于承载面板级后台工作。插件当前支持安装、状态检查和通过 `index.py` 执行功能方法，但没有一套标准方式声明“插件安装后需要周期执行的方法”。

`ha_manager` 需要周期执行两类工作：向云监控上报主备状态，以及轮询云监控保存的期望主备状态。如果在插件内部新增独立守护进程或 crontab，会让生命周期、卸载清理和故障隔离变复杂。

这个设计需要贴合现有插件加载方式，保持 `task.py` 主循环轻量，并保证单个插件任务失败不会影响其他面板任务。

## Goals / Non-Goals

**Goals:**

- 允许插件在 `info.json` 中声明周期性方法调用。
- 由 `task.py` 自动发现已安装插件并执行声明任务。
- 将执行范围限制在插件声明的 `func` 和 JSON `args` 内。
- 支持执行间隔、超时、启用/禁用和简单执行状态记录。
- 将该机制接入 `ha_manager`，不依赖额外守护进程或 crontab。

**Non-Goals:**

- 不重构整个面板任务引擎。
- 不允许从插件元数据中执行任意 shell 命令。
- 不为调度注册新增云监控 API。
- 不在本变更中把插件业务逻辑迁出 `index.py`。

## Decisions

### 1. 使用 `info.json.tasks` 作为声明式任务列表

每个任务项描述一次插件方法调用，核心字段为 `func` 和 `args`，调度字段为 `interval`、`timeout`、`enabled`，展示字段可选 `title`。

理由：`info.json` 已经是插件安装和展示所依赖的元数据。把任务声明放在这里，安装时行为可见，卸载时也天然随插件失效。

备选方案：

- 在插件目录下新增独立调度文件。这样会增加一个需要维护的配置文件，也不如 `info.json` 直观。
- 在数据库中保存插件任务定义。这样会让插件包和运行配置分离，安装/卸载同步更复杂。

### 2. 由 `task.py` 负责调度和执行

面板任务进程扫描已安装插件，读取插件元数据，在任务到达执行间隔后调用声明方法。

理由：`task.py` 已经是面板常驻协调器，复用它可以统一生命周期，避免每个插件新增服务。

备选方案：

- 插件自己创建 cron 任务。这样调度控制分散，卸载清理容易遗漏。
- 新增独立调度守护进程。这样会重复 `task.py` 的职责，并增加新的故障面。

### 3. 只执行声明的插件函数，不执行任意命令

调度器只接受 `info.json.tasks[].func` 中声明的插件方法名，并映射为：

```text
python3 /www/server/jh-panel/plugins/<name>/index.py <func> <args_json>
```

理由：这样实现简单，隔离性比进程内 import 更好，也避免把插件元数据变成任意命令执行入口。

备选方案：

- 允许声明任意 shell 字符串。范围过大，不适合作为元数据驱动的通用调度能力。
- 在 `task.py` 进程内 import 插件模块并直接调用。性能更高，但耦合更强，插件异常也更容易影响面板任务进程。

### 4. 执行状态保持轻量且有边界

调度器记录每个插件任务的最近执行时间、最近成功/失败状态和短错误摘要。不在调度器中保存完整历史。

理由：`task.py` 长期运行，不应因为插件任务输出持续积累大量状态或日志。

备选方案：

- 保存每次执行的完整记录。查询更完整，但第一版没有必要，也会增加存储和清理成本。

### 5. 插件任务失败必须隔离

单个插件任务失败、超时或返回非零状态时，调度器只记录失败，并继续处理其他插件任务和面板任务。

理由：这样可以保护面板已有系统监控、任务队列和服务守护能力，不受单个插件配置错误或网络异常影响。

备选方案：

- 让失败中断整个任务循环。这样一个插件问题会扩散为面板后台任务问题，不可接受。

## Risks / Trade-offs

- [插件任务输出过多] -> 只保存短摘要，并限制捕获输出长度。
- [长时间任务阻塞调度] -> 每个任务执行超时控制，并隔离单次执行。
- [插件元数据和安装状态不一致] -> 每次扫描读取已安装插件当前 `info.json`，并以安装检查路径作为是否执行的依据。
- [失败任务频繁重试造成负载] -> 设置最小执行间隔，并在连续失败时增加简单退避。

## Migration Plan

1. 在 `ha_manager/info.json` 中新增 `tasks` 声明。
2. 扩展 `task.py`，扫描已安装插件的定时任务声明并执行到期任务。
3. 增加轻量调度状态，记录最近执行、最近错误和下次可执行时间。
4. 验证面板任务进程运行时，`ha_manager` 能按配置上报和轮询。
5. 回滚时移除插件 `tasks` 声明；调度器需要兼容没有 `tasks` 或空 `tasks` 的插件。

## Open Questions

- 调度状态放在独立面板数据文件中，还是只保存在内存中并在重启后重新计算？
- `args` 第一版是否只允许 JSON 对象，还是允许数组和基础类型以保留扩展性？
- 连续失败任务使用固定重试间隔，还是使用指数退避？
