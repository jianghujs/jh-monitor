## Context

检查工具已有普通定时同步日志解析器，实时任务原先提前返回。日报已有 fixtime_abnormal_tasks 的摘要与概览通路。

## Goals / Non-Goals

**Goals:** 所有已启用任务都必须有最近运行日志，且日志内容正常；检查结果进入既有日报。

**Non-Goals:** 不识别独立兜底计划，不扫描历史运行，不汇总失败次数和恢复状态，不新增采集字段，不修改任务执行命令。

## Decisions

1. 删除实时任务提前返回，与普通定时任务共用 _inspect_sync_task。按修改时间选最新 run_* 文件，无目录或无日志均返回异常。
2. getRsyncdInfo 未指定 start_timestamp 时使用当前时间减 24 小时；最新日志早于此时间判异常，边界时刻有效。两类任务规则一致。
3. 日志存在且未过期后调用既有 _check_fixtime_sync_status，保留删除比例阈值、错误识别和 23/24 警告的现有规则。
4. 日报继续只取最新检查快照，明细合并展示实时任务和普通定时任务；异常复用既有列表，动态文本转义。
5. 原先新增的 fallback 字段、历史聚合、恢复标记和执行开始结束标记全部移除。index.py 恢复原有执行行为。

## Risks / Trade-offs

- [同步计划超过一天] → 本次按“最近日志”要求统一采用 24 小时口径；日志过期会提醒。
- [运行日志尚未完整] → 与普通定时任务保持一致，缺少完成汇总判异常，不新增运行状态协议。
- [旧插件仍跳过实时日志解析] → 被采集主机须同步更新 tool_check.py。

## Migration Plan

发布监控端分析器并更新被采集主机检查工具；采集器、同步计划和 ES 映射无需改变。需要加载常驻进程新代码时使用 jhm 1 -y。回滚恢复这两个文件即可。
