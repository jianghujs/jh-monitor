## ADDED Requirements

### Requirement: 新增支持可选自定义密钥
系统 SHALL 在新增管理员或普通调用密钥时接受可选 key；缺省或空字符串自动生成现有格式的随机密钥，非空则使用原文，不修剪、不变更大小写、不添加前缀。非空值 MUST 为 32～128 位 ASCII 字母、数字、下划线或短横线。

#### Scenario: 自动生成保持兼容
- **WHEN** 管理员新增时不传 key 或传空字符串
- **THEN** 生成 jhm_ 加 64 位随机十六进制字符，保存后可认证和取回原文

#### Scenario: 合法边界和自定义内容
- **WHEN** 指定符合字符规则、长度分别为 32、68、128 的密钥
- **THEN** 创建成功，取回及鉴权使用完全相同的大小写敏感原文

#### Scenario: 无效输入
- **WHEN** 非空 key 为非字符串、长度为 31 或 129，或含空格、换行、中文及其他非法字符
- **THEN** 后端拒绝并返回规则说明，不写入密钥记录、不回显输入；纯空格不视为留空

### Requirement: 表单提供输入和显隐交互
新增调用密钥表单 SHALL 提供可选密钥输入与眼睛按钮，默认隐藏，说明留空自动生成及跨机房复用用途；前端校验与后端一致，列表继续脱敏展示。

#### Scenario: 粘贴另一机房密钥
- **WHEN** 管理员在新增表单粘贴密钥并点击眼睛按钮、切换管理员/普通类型
- **THEN** 显隐切换不改变内容，类型切换保留输入，保存发送原文与所选权限

#### Scenario: 取消并重新新增
- **WHEN** 输入密钥后取消，再打开新增表单
- **THEN** 不创建记录，新表单密钥为空且默认隐藏

### Requirement: 编辑不更改密钥原文
系统 SHALL 维持编辑仅修改元信息的语义，不显示可编辑原文输入。update 请求非空 key MUST 明确拒绝，不能暗中更新或误报原文更新成功。

#### Scenario: 正常编辑权限
- **WHEN** 修改名称、备注、类型、权限、有效期或状态且不传非空 key
- **THEN** 保留原文、摘要及密文，原有鉴权按更新后的元信息执行

#### Scenario: 请求尝试修改原文
- **WHEN** update 携带非空 key
- **THEN** 返回明确的参数错误，不修改原文或其他字段

### Requirement: 单部署密钥唯一且不覆盖已有记录
系统 SHALL 利用 key_hash 唯一约束拒绝重复原文，包括与停用或过期记录重复；并发创建同一原文至多成功一次，重复返回 HTTP 409，不改写已有记录，不回显原文。

#### Scenario: 重复创建
- **WHEN** 指定本部署已经存在的密钥，不论原记录是否启用或过期
- **THEN** 提示密钥已存在，原记录的权限、类型、有效期和启用状态保持不变

#### Scenario: 并发冲突
- **WHEN** 两个并发请求创建同一合法原文
- **THEN** 一条创建成功，另一条返回重复错误，数据库仅保留一条对应摘要记录

### Requirement: 自定义和旧密钥共用认证及权限规则
系统 SHALL 允许新格式的 Bearer 凭据并兼容已有 68 字符密钥，按原文摘要查找，继续检查总开关、启用、有效期和权限。管理调用密钥仍要求完整管理员登录、同源和 CSRF 校验。

#### Scenario: 旧密钥继续可用
- **WHEN** 升级前创建的有效随机密钥调用原有授权接口
- **THEN** 不需迁移或重置，仍可正常认证

#### Scenario: 自定义串不绕过权限
- **WHEN** 自定义串格式正确但未登记、已停用、已过期、无对应权限或 API 总开关关闭
- **THEN** 根据既有 401/403 规则拒绝；普通密钥只访问已授权接口，管理员密钥沿用全部接口权限

#### Scenario: 禁止外部凭据管理密钥
- **WHEN** 未完整登录或使用调用密钥请求创建，或登录请求缺少有效同源/CSRF 验证
- **THEN** 拒绝创建，不因提供自定义 key 放宽管理权限

### Requirement: 两个部署可独立保存并使用同一原文
系统 SHALL 允许两个独立数据库保存同一调用密钥，分别使用各自的加密主密钥、nonce 和 key_id 加密；不要求共享主密钥文件，不自动同步权限和状态。

#### Scenario: 同一凭据调用两边
- **WHEN** 两套实例分别保存相同原文，均启用 API 且授权 ha:read
- **THEN** 相同 Bearer 凭据可查询两边关系接口；两边查看原文一致，密文不同

#### Scenario: 单边配置变化
- **WHEN** A 停用、过期、取消 ha:read 或关闭 API，而 B 仍有效
- **THEN** A 拒绝请求，B 继续成功，B 的配置不被同步改变

### Requirement: 保持原文可恢复与脱敏边界
系统 SHALL 复用现有摘要和 AES-GCM 存储、授权查看/复制、no-store 响应及主密钥完整性校验；列表、普通错误和操作日志不得记录完整原文，前端不得持久化保存输入。

#### Scenario: 查看自定义原文
- **WHEN** 管理员完成授权查看或复制自定义密钥
- **THEN** 返回与创建输入一致的原文并保留 no-store；普通列表只提供脱敏前缀

#### Scenario: 原主密钥丢失或不匹配
- **WHEN** 已有加密记录但本地主密钥缺失或不可解密，管理员创建或查看密钥
- **THEN** 按既有错误流程拒绝，不能静默生成新主密钥覆盖旧凭据
