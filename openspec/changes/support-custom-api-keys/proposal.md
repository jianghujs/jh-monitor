## Why

两个机房分别部署云监控，调用程序希望切换监控地址时继续使用同一个 API Key。当前调用密钥只能随机生成，无法把一个机房的密钥原文用于另一个机房。

## What Changes

- 新增调用密钥表单增加“密钥串（可选）”：留空自动生成，填写则使用指定原文，支持显示/隐藏。管理员和普通密钥均可使用。
- 自定义串接受 32～128 位 ASCII 英文字母、数字、下划线、短横线，大小写敏感；拒绝空白字符和非法值，不静默修改输入。
- 创建接口与鉴权共同支持自定义格式，兼容已有 jhm_ 随机密钥和 Bearer 调用方式。
- 单个云监控内禁止重复密钥，两个独立部署可创建相同原文；继续加密保存、脱敏展示及授权查看原文。
- 编辑已有记录不修改密钥串。两边权限、启用状态、有效期仍独立管理。
- 验证两套独立数据库和加密主密钥下，同一 API Key 可调用两边接口；补充部署与配置说明。

## Capabilities

### New Capabilities

- `custom-api-key-creation`: 新增时指定调用密钥、格式校验、重复处理、旧密钥兼容和跨部署认证。

### Modified Capabilities

无。现有主规格没有 API 调用密钥能力，新增专项规格；现有主备管理协议不变。

## Impact

- route/static/app/api-keys.js：新增表单、显示/隐藏、校验及请求参数。
- class/core/api_key_routes.py：仅创建时接收自定义 key 参数。
- class/core/api_key_store.py：创建时选择自动/指定原文、统一格式规则、重复错误与认证兼容。
- test/test_external_api_keys.py：新增自定义值、并发重复、双实例、权限和旧行为回归。
- 复用 api_key 表、唯一摘要索引和 AES-GCM 存储，不新增 SQL 字段、依赖或接口。
- 江湖数据同步无需改调用代码；两套云监控需更新代码，使用各自的 API 总开关及相同调用密钥。
