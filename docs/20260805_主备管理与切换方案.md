# 主备管理与切换方案

## 1. 方案目标

在江湖云监控中新增“主备管理”模块，用于绑定两台江湖面板服务器的主备关系、查看主备状态、发起手动切换，并追踪切换过程。

第一版只做手动切换，不做自动故障切换。云监控负责保存期望状态、实际状态、切换状态和日志地址；两台江湖面板都安装主备管理插件，由插件轮询云监控 API 获取期望状态并执行真实切换。

切换过程要覆盖江湖面板现有上下线脚本的全部流程：

| 脚本 | 路径 | 说明 |
| --- | --- | --- |
| 下线脚本 | `/www/server/jh-panel/scripts/os_tool/vm/default/switch__generate_offline.sh` | 将当前主机切换为备用机状态，关闭线上服务和相关提醒，开启备份/恢复类任务 |
| 上线脚本 | `/www/server/jh-panel/scripts/os_tool/vm/default/switch__generate_online.sh` | 将当前主机切换为主机状态，执行数据准备、主从切换、服务启动和提醒恢复 |

## 2. 核心结论

| 项目 | 结论 |
| --- | --- |
| 切换方式 | 第一版仅支持手动切换 |
| 插件部署 | 两台江湖面板都安装主备管理插件 |
| 控制边界 | 云监控只保存期望状态，插件执行实际切换 |
| 状态同步 | 插件轮询云监控 API 获取期望状态，执行后上报实际状态 |
| 多机房上报 | 两边机房各自部署云监控；插件通过 SSH 采集对端状态和日志后，统一上报给本机房云监控 |
| 日志传输 | 切换状态和日志统一通过 API 传输，不使用 filebeat/ES |
| 日志存储 | 每次切换在云监控 `/www/server/jh-monitor/logs/ha_switch/` 下保存一份日志文件 |
| SQLite 职责 | 只保存状态、当前步骤、错误摘要、日志地址等结构化索引 |
| 外部回调 | 云监控确认实际状态切换完成后，回调外部系统，例如江湖数据同步 |

## 3. 总体架构

```text
管理员在云监控发起手动切换
        │
        ▼
云监控更新期望状态 desired_role，并创建 switch_run
        │
        ▼
旧主机插件轮询到 offline 阶段，执行下线流程
        │
        ├─ 上报状态
        ├─ 追加日志到云监控日志文件
        └─ 上报 offline_done / failed
        │
        ▼
新主机插件轮询到 online 阶段，执行上线流程
        │
        ├─ 上报状态
        ├─ 追加日志到云监控日志文件
        └─ 上报 online_done / failed
        │
        ▼
云监控校验实际状态 actual_role 是否收敛
        │
        ▼
切换成功后执行外部回调
```

主体职责：

| 主体 | 职责 |
| --- | --- |
| 江湖云监控 | 绑定主备关系、保存期望状态、创建切换任务、接收状态和日志、展示告警、执行外部回调 |
| 主备管理插件 | 周期自检、轮询期望状态、执行上下线切换、上报实际状态和日志 |
| 江湖面板上下线脚本 | 提供下线/上线的实际操作流程来源 |
| 外部系统 | 接收云监控切换完成回调，例如江湖数据同步切换数据库 |

### 3.1 多机房双云监控架构

适用场景：两台主备江湖面板部署在两个机房，每个机房各自部署一套江湖云监控。任意一边云监控都需要看到这组主备关系中两台机器各自的状态、切换状态和日志。

设计原则：云监控不主动跨机房 SSH，也不直接拉取另一边日志。跨机房采集由 `ha_manager` 插件负责，插件通过已绑定的 SSH 通道采集对端状态和日志，再由本机房内可访问云监控的插件统一上报。

```text
机房 A
  云监控 A
  面板 A + ha_manager 插件
      ├─ 采集 A 本机状态和日志
      ├─ 通过 SSH 采集 B 的状态和日志
      └─ 上报 A+B 状态和日志到云监控 A

机房 B
  云监控 B
  面板 B + ha_manager 插件
      ├─ 采集 B 本机状态和日志
      ├─ 通过 SSH 采集 A 的状态和日志
      └─ 上报 B+A 状态和日志到云监控 B
```

主体职责补充：

| 主体 | 补充职责 |
| --- | --- |
| 本机插件 | 采集本机实际角色、自检状态、切换状态和本机日志 |
| 对端采集 | 通过 SSH 获取对端插件状态文件、切换状态和日志增量 |
| 聚合上报插件 | 把“本机 + 对端”的状态和日志统一通过 API 上报到本机房云监控 |
| 云监控 | 只接收插件 API 上报，按 `origin_host_id` 区分两台机器的数据来源 |

如果插件无法通过 SSH 获取对端状态，不能直接把对端判定为业务离线，应上报“采集失败/未知”，由云监控展示橙色提醒或红色异常。

## 4. 主备状态模型

主备管理需要区分“配置关系、期望状态、实际状态”。不能只依赖 `host.is_master` 一个布尔字段。

| 状态层级 | 字段示例 | 说明 |
| --- | --- | --- |
| 主备关系 | `pair_id`, `primary_host_id`, `standby_host_id` | 两台主机的绑定关系 |
| 期望状态 | `desired_master_host_id` | 管理员希望哪台主机成为主机 |
| 实际状态 | `actual_role`, `actual_master_host_id` | 插件自检和切换后上报的真实状态 |
| 切换状态 | `switch_run.status` | 当前是否在切换、是否失败、是否完成 |

状态示例：

| 状态 | 说明 |
| --- | --- |
| `stable_synced` | 期望状态与实际状态一致 |
| `desired_changed` | 云监控期望状态已变更，插件尚未完成切换 |
| `offlining` | 旧主机正在执行下线流程 |
| `onlining` | 新主机正在执行上线流程 |
| `verifying` | 云监控正在等待实际状态收敛 |
| `success` | 本次切换完成 |
| `failed` | 本次切换失败，需要人工处理或重试 |
| `drifted` | 期望状态与实际状态长时间不一致 |
| `unknown` | 插件长时间未上报 |

## 5. 手动切换流程

### 5.1 发起切换

适用场景：管理员看到主机离线红色异常，或看到部分状态橙色提醒后，决定手动切换到备用机。

操作流程：

1. 管理员在云监控“主备管理”页面选择一组主备关系。
2. 点击“切换到备用机”。
3. 云监控弹出切换选项确认页，展示本次切换涉及的下线主机、上线主机、上线参数和风险提示。
4. 管理员确认后，云监控创建 `switch_run`，更新 `desired_master_host_id`。
5. 云监控生成本次切换日志文件。

### 5.2 旧主机下线

适用场景：当前主机需要从主机状态降为备用机状态。

下线流程来源于 `switch__generate_offline.sh`，包括：

| 分组 | 步骤 |
| --- | --- |
| 计划任务 | 开启数据库备份、xtrabackup、xtrabackup-inc 全量/增量备份 |
| 计划任务 | 关闭网站配置备份、插件配置备份、lsyncd 实时任务定时同步、Let's Encrypt 续签任务 |
| 计划任务 | 开启恢复网站配置、恢复插件配置定时任务 |
| 监控提醒 | 关闭 SSL 证书到期预提醒 |
| SSH 同步 | 将同步公钥加入 `authorized_keys` |
| rsync | 关闭 rsyncd 任务，停止 lsyncd，清理 rsync 进程 |
| Web 服务 | 关闭 OpenResty |
| 业务提醒 | 关闭主从同步异常提醒、Rsync 状态异常提醒 |

插件执行要求：

1. 下线开始前向云监控上报 `offlining`。
2. 每个关键步骤开始、成功、失败都通过 API 追加日志。
3. 如果步骤失败且策略为停止，切换任务进入 `failed`。
4. 如果步骤失败但允许继续，记录橙色提醒，流程继续。
5. 下线完成后上报 `offline_done`。

### 5.3 新主机上线

适用场景：备用机需要提升为主机。

上线流程来源于 `switch__generate_online.sh`，包括：

| 分组 | 步骤 |
| --- | --- |
| 预上线 | 可选执行 xtrabackup 增量恢复 |
| 预上线 | 可选检查主备服务器 checksum |
| 预上线 | 可选从目标服务器同步文件 |
| 预上线 | 可选恢复网站配置 |
| 预上线 | 可选恢复插件配置 |
| 数据库 | 可选将当前数据库提升为主 |
| 计划任务 | 关闭数据库备份、xtrabackup、xtrabackup-inc 全量/增量备份 |
| 计划任务 | 开启网站配置备份、插件配置备份、lsyncd 实时任务定时同步、Let's Encrypt 续签任务 |
| 计划任务 | 关闭恢复网站配置、恢复插件配置定时任务 |
| 监控提醒 | 开启 SSL 证书到期预提醒 |
| SSH 同步 | 从 `authorized_keys` 删除同步公钥 |
| rsync | 启用 rsyncd 任务，重启 lsyncd |
| Web 服务 | 启动 OpenResty |
| 业务提醒 | 开启邮件通知、主从同步异常提醒、Rsync 状态异常提醒 |

插件执行要求：

1. 上线开始前向云监控上报 `onlining`。
2. 使用云监控下发的上线配置替代脚本中的人工 prompt。
3. 每个关键步骤通过 API 追加日志。
4. 上线完成后执行自检并上报 `actual_role=master`。
5. 云监控确认新主机为实际主机后，切换进入 `success`。

## 6. 上线参数配置

上线脚本当前存在交互式输入。主备插件无人值守执行时，需要把这些参数配置化。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `local_ip` | 当前面板 IP | 当前上线主机 IP |
| `remote_ip` | 对端面板 IP | 旧主机或同步来源 IP |
| `remote_ssh_port` | `10022` | 同步文件时连接对端 SSH 端口 |
| `run_xtrabackup_inc_restore` | `false` | 是否执行 xtrabackup 增量恢复 |
| `run_checksum` | `true` | 是否检查主备服务器 checksum |
| `allow_checksum_diff` | `false` | checksum 不一致时是否允许继续 |
| `sync_files` | `true` | 是否从目标服务器同步文件 |
| `sync_file_dirs` | `/www/wwwroot,/www/wwwstorage` | 需要同步的目录 |
| `sync_ignore_dirs` | `node_modules,logs,run` | 同步时忽略的目录 |
| `restore_site_setting` | `false` | 是否恢复网站配置 |
| `site_setting_backup_dir` | `/www/backup/site_setting` | 网站配置备份目录 |
| `site_setting_file` | 自动取最新 | 网站配置备份文件 |
| `restore_plugin_setting` | `false` | 是否恢复插件配置 |
| `plugin_setting_backup_dir` | `/www/backup/plugin_setting` | 插件配置备份目录 |
| `plugin_setting_file` | 自动取最新 | 插件配置备份文件 |
| `promote_mysql_master` | `true` | 是否将当前数据库提升为主 |

配置来源建议：

| 来源 | 说明 |
| --- | --- |
| 主备关系默认配置 | 每组主备关系的常用参数，平时维护 |
| 发起切换时覆盖 | 本次切换临时参数，例如是否恢复网站配置 |
| 插件本地配置 | 云监控地址、`pair_id`、`host_id`、签名密钥 |

界面约束：上线参数不再作为插件独立页签长期暴露；当用户从插件首页发起“切换为主”时，在确认弹窗中展示并允许临时调整本次上线参数。

## 8. 日志文件设计

### 8.1 日志目录

切换日志统一写入云监控本地目录：

```text
/www/server/jh-monitor/logs/ha_switch/
```

按月份分目录，每次切换一个日志文件：

```text
/www/server/jh-monitor/logs/ha_switch/2026-08/HSR_20260805120000_abcd.log
```

SQLite 中建议保存相对路径：

```text
logs/ha_switch/2026-08/HSR_20260805120000_abcd.log
```

### 8.2 日志格式

日志文件保留可读文本，不要求每行都是 JSON，便于运维直接查看。

建议格式：

```text
[2026-08-05 12:00:01] [H_A] [offline] [running] 关闭 OpenResty
|- 开始关闭 OpenResty...

[2026-08-05 12:00:05] [H_A] [offline] [success] 关闭 OpenResty
|- 关闭 OpenResty 完成

[2026-08-05 12:01:10] [H_B] [online] [warning] checksum 检查
|- checksum 结果存在差异，用户选择忽略并继续
```

### 8.3 日志追加规则

插件上报日志时只传 `switch_run_id`，不能传任意日志路径。云监控根据 `switch_run_id` 查询 `log_path` 后追加日志。

为避免网络重试造成重复追加，插件上报日志需要带序号：

| 字段 | 说明 |
| --- | --- |
| `event_id` | 日志事件唯一 ID，推荐 `<switch_run_id>-<host_id>-<seq>` |
| `seq` | 当前主机在本次切换中的递增序号 |
| `switch_run_id` | 切换任务 ID |
| `host_id` | 兼容字段，建议等同于 `origin_host_id` |
| `origin_host_id` | 日志实际来自哪台主机 |
| `report_host_id` | 由哪台插件上报到当前云监控 |
| `collect_method` | `local` 表示本机采集，`ssh_peer` 表示通过 SSH 采集对端 |
| `phase` | `offline/online/verify/callback` |
| `step` | 当前步骤名称 |
| `status` | `running/success/warning/error` |
| `log` | 日志正文 |

示例：

```json
{
  "switch_run_id": "HSR_20260805160000_7bc0",
  "origin_host_id": "H_PANEL_B",
  "report_host_id": "H_PANEL_A",
  "collect_method": "ssh_peer",
  "phase": "online",
  "step": "promote_mysql_master",
  "status": "running",
  "seq": 42,
  "log": "将当前数据库提升为主"
}
```

云监控处理逻辑：

```text
1. 校验签名和 switch_run_id 归属
2. 根据 `event_id` 或 `origin_host_id + seq` 做幂等判断
3. 更新 SQLite 当前状态和步骤摘要
4. 追加日志到 logs/ha_switch/YYYY-MM/<switch_run_id>.log
5. 返回确认结果
```

云监控展示日志时按 `origin_host_id` 拆分为两台机器各自的日志，同时保留完整日志文件，方便追踪整次切换。

### 8.4 插件本地日志和对端日志缓存

插件需要在本机保留可采集的状态文件和日志文件，供对端插件通过 SSH 拉取。

| 类型 | 建议路径 | 说明 |
| --- | --- | --- |
| 本机状态快照 | `/www/server/jh-panel/plugins/ha_manager/data/state.json` | 当前角色、健康状态、最近切换任务、最近日志序号 |
| 本机切换日志 | `/www/server/jh-panel/plugins/ha_manager/logs/switch/<switch_run_id>.log` | 本机执行 offline/online 流程产生的日志 |
| 对端日志缓存 | `/www/server/jh-panel/plugins/ha_manager/logs/peer/<peer_host_id>/<switch_run_id>.log` | 本机通过 SSH 从对端采集到的日志缓存 |

对端日志缓存只作为补偿和上报队列使用，云监控最终仍以 `/www/server/jh-monitor/logs/ha_switch/` 下的日志文件作为页面展示和追踪入口。

## 9. API 设计

### 9.1 页面管理 API

页面管理 API 走登录态，建议新增 `ha_api` 或 `master_standby_api`。

| API | 用途 |
| --- | --- |
| `/ha/list` | 查询主备关系列表 |
| `/ha/detail` | 查询主备关系详情 |
| `/ha/bind_pair` | 绑定两台主机为主备关系 |
| `/ha/update_pair_config` | 更新主备关系默认切换配置 |
| `/ha/request_switch` | 发起手动切换，只更新期望状态并创建切换任务 |
| `/ha/get_switch_run` | 查询切换任务状态 |
| `/ha/get_switch_log` | 按 offset 读取切换日志内容 |
| `/ha/retry_switch` | 重试失败阶段 |
| `/ha/cancel_switch` | 取消尚未被插件领取的切换任务 |
| `/ha/update_callback` | 配置切换完成回调 |

### 9.2 插件 API

插件 API 可放在 `/pub` 下，但必须使用签名鉴权。

| API | 用途 |
| --- | --- |
| `/pub/ha_pull_desired_state` | 插件轮询期望状态和待执行任务 |
| `/pub/ha_report_state` | 插件上报实际角色、自检状态 |
| `/pub/ha_report_switch_event` | 插件上报切换状态和日志片段 |
| `/pub/ha_ack_switch_phase` | 插件确认某个阶段已领取、完成或失败 |

### 9.3 签名要求

插件接口不能只依赖 `host_id`。建议使用 HMAC 签名。

请求参数：

| 字段 | 说明 |
| --- | --- |
| `pair_id` | 主备关系 ID |
| `host_id` | 主机 ID |
| `timestamp` | 请求时间戳 |
| `nonce` | 随机串 |
| `signature` | HMAC 签名 |

签名内容建议包含请求路径和规范化 payload：

```text
signature = HMAC_SHA256(secret, method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + body_sha256)
```

云监控校验：

1. `pair_id` 和 `host_id` 必须存在并已绑定。
2. `timestamp` 不能超过允许窗口，例如 5 分钟。
3. `nonce` 在窗口期内不能重复。
4. `signature` 必须匹配当前主机或主备关系密钥。

## 10. 主备管理插件设计

插件安装在两台江湖面板上，职责是自检、轮询、执行、上报。

### 10.1 插件本地配置

建议配置项：

| 配置项 | 说明 |
| --- | --- |
| `monitor_url` | 云监控地址 |
| `pair_id` | 主备关系 ID |
| `host_id` | 当前主机 ID |
| `peer_host_id` | 对端主机 ID |
| `secret` | 插件 API 签名密钥 |
| `poll_interval` | 轮询期望状态间隔 |
| `report_interval` | 自检状态上报间隔 |
| `local_role` | 本地缓存角色 |

配置界面说明：

| 页面 | 说明 |
| --- | --- |
| 绑定主备 | 输入对方机器公网 IP、SSH 端口、SSH 用户和对方公钥，先测试 SSH 连接，再保存绑定关系 |
| 云监控 | 单独配置云监控地址；默认留空，留空时插件不上传状态和切换日志，也不轮询云监控期望状态 |
| 总览 | 展示本机角色、对端信息、自检摘要和最近切换任务，并提供本机切换入口 |

`pair_id` 是内部配置值，由插件保存绑定关系时自动生成或由云监控下发，不在插件界面提供手动输入框。

### 10.2 周期任务

| 任务 | 说明 |
| --- | --- |
| 拉取期望状态 | 周期调用 `/pub/ha_pull_desired_state`，发现待执行阶段后领取任务 |
| 本地自检 | 检查面板在线状态、mysql、rsync/lsyncd、OpenResty 等状态 |
| SSH 采集对端状态 | 通过绑定时配置的 SSH 信息读取对端 `state.json`、切换状态和日志增量 |
| 状态上报 | 周期调用 `/pub/ha_report_state` 上报实际角色和健康状态 |
| 日志补偿 | 网络失败时重试上报未确认日志事件 |

### 10.3 执行器要求

现有上下线脚本以交互式生成为主。插件执行器建议把流程拆成可调用步骤，或者封装为非交互模式。

执行器至少需要支持：

| 能力 | 说明 |
| --- | --- |
| 非交互参数 | 使用云监控下发的 `options_json` 替代 prompt |
| 步骤级日志 | 每一步开始、成功、失败都上报云监控 |
| 失败策略 | 支持失败停止、失败继续并记 warning |
| 幂等执行 | 重试时已成功步骤不重复执行，或重复执行不造成破坏 |
| 本地锁 | 同一台主机同一时间只能执行一个切换任务 |

### 10.4 插件本地手动切换

除云监控发起切换外，插件首页也需要支持本机手动切换，便于运维直接在当前江湖面板上操作。

| 当前角色 | 首页操作 | 弹窗内容 | 执行后展示 |
| --- | --- | --- | --- |
| `master` | 切换为备 | 下线流程摘要、确认对端可接管业务 | 进入切换日志页，展示本机下线流程日志 |
| `standby` | 切换为主 | 上线参数、本机/对端 IP、SSH 端口、同步目录、checksum、文件同步、数据库提升等选项 | 进入切换日志页，展示本机上线流程日志 |

本地发起切换的执行边界与云监控发起切换一致，都必须经过本地执行锁、步骤级日志和状态上报。若配置了云监控地址，插件应把本地切换生成的状态和日志同步上报云监控；若未配置云监控地址，则只保留本机日志和本机状态。

### 10.5 插件聚合上报

在双机房场景下，每个机房的云监控都只能稳定访问本机房内的面板插件，因此插件需要承担聚合上报职责。

聚合上报内容：

| 数据 | 本机来源 | 对端来源 | 云监控展示 |
| --- | --- | --- | --- |
| 实际角色 | 本机自检 | SSH 读取对端状态快照 | 主机列表、组别概览 |
| 自检状态 | 本机检查 mysql、rsync、OpenResty、插件锁 | SSH 读取对端状态快照 | 自检状态按主机分别展示 |
| 切换状态 | 本机执行器状态 | SSH 读取对端切换状态 | 切换状态按主机分别展示 |
| 切换日志 | 本机日志文件 | SSH 增量读取对端日志 | 切换日志按 `origin_host_id` 分别展示 |

采集失败时的状态表达：

| 场景 | 上报状态 | 页面提醒 |
| --- | --- | --- |
| SSH 连接失败 | `collect_status=failed`、`health_status=unknown` | 橙色提醒：无法采集对端状态 |
| 对端状态文件不存在 | `collect_status=missing_state` | 橙色提醒：对端插件未初始化或版本不匹配 |
| 对端日志读取失败 | `collect_status=partial` | 橙色提醒：状态可用但日志不完整 |
| 对端插件明确上报离线 | `online_status=offline` | 红色异常：主机离线 |

注意：`collect_status=failed` 表示“本插件无法采集对端”，不等同于“对端业务离线”。云监控需要把这两类状态分开显示。

## 11. 告警和提醒

第一版告警不做复杂故障判定，重点让用户知道是否需要切换。

### 11.1 红色异常

| 异常 | 说明 |
| --- | --- |
| 主机离线 | 当前实际主机长时间未上报或主机状态离线 |
| 双主 | 两台主机都上报 `master` |
| 双备 | 两台主机都上报 `standby` |
| 切换失败 | 任一关键阶段失败 |
| 状态不一致 | 期望主机与实际主机长时间不一致 |
| 插件失联 | 插件超过阈值未上报 |

### 11.2 橙色提醒

| 提醒 | 说明 |
| --- | --- |
| mysql 状态异常 | mysql 检查不正常，但尚未确认主机不可用 |
| rsync 状态异常 | rsyncd、lsyncd 或同步任务状态异常 |
| OpenResty 状态异常 | Web 服务状态异常 |
| checksum 差异 | checksum 检查存在差异但用户选择忽略 |
| 非关键步骤失败 | 失败后允许继续的步骤 |
| 回调失败 | 切换完成后外部回调失败，等待重试 |

## 12. 外部回调

外部回调由云监控执行，不由插件直接回调。

触发条件：

```text
1. offline 阶段完成
2. online 阶段完成
3. 新主机上报 actual_role=master
4. 旧主机上报 actual_role=standby，或旧主机下线阶段已确认完成
5. switch_run 状态变为 success
```

回调 payload 示例：

```json
{
  "pair_id": "HA_xxx",
  "switch_run_id": "HSR_20260805120000_abcd",
  "old_master_host_id": "H_A",
  "new_master_host_id": "H_B",
  "actual_master_host_id": "H_B",
  "status": "success",
  "finished_at": "2026-08-05 12:10:00"
}
```

回调失败处理：

1. `switch_run` 保持 `success`，但回调状态标记为失败或重试中。
2. 回调错误写入本次切换日志文件。
3. 页面显示橙色提醒。
4. 云监控按退避策略重试，或提供人工重试按钮。

## 15. 风险和注意事项

| 风险 | 处理建议 |
| --- | --- |
| 脚本交互阻塞 | 上线参数必须配置化，插件执行器必须非交互 |
| 脑裂 | 第一版只做手动切换；插件领取任务前校验当前 `switch_run` 阶段和锁 |
| 重复执行 | 使用 `switch_run_id`、阶段状态、本地锁、日志 `seq` 做幂等 |
| 日志重复 | 插件上报 `event_id/seq`，云监控去重后再追加日志 |
| 日志过大 | 单个日志文件设置大小上限，超限后追加截断提示 |
| 插件失联 | 云监控按 `last_report_at` 判定红色异常或未知状态 |
| SSH 采集失败被误判为主机离线 | 区分 `collect_status` 和 `online_status`，采集失败先显示采集异常，不直接判定业务离线 |
| 双云监控数据不一致 | 两边云监控都以各自机房插件上报为准，页面显示最近上报时间、上报主机和采集方式 |
| 对端日志重复上传 | 使用 `origin_host_id + seq` 或 `event_id` 做幂等，避免本机和对端采集同时写重复日志 |
| 回调失败 | 不影响切换成功状态，但页面显示橙色提醒并支持重试 |
| 现有 `host.is_master` 字段兼容 | 可作为展示兼容字段，但主备模块状态以新表为准 |

## 16. 第一版验收标准

1. 云监控可以绑定两台主机为一组主备关系。
2. 两台江湖面板插件都能向云监控上报实际角色和健康状态。
3. 每个机房的插件都能通过 SSH 采集对端状态和日志，并把两台机器的数据统一上报到本机房云监控。
4. 云监控页面能显示当前主机、期望主机、健康摘要和最近上报时间。
5. 组别详情中“主机列表、自检状态、切换状态、切换日志”都能按两台机器分别展示。
6. 管理员可以手动发起从 A 切换到 B。
7. A 插件执行下线流程并通过 API 上报状态和日志。
8. B 插件执行上线流程并通过 API 上报状态和日志。
9. 云监控在 `/www/server/jh-monitor/logs/ha_switch/` 下生成并保存本次切换日志。
10. SQLite 只保存切换状态、当前步骤、错误摘要、日志地址和必要配置。
11. 切换日志按 `origin_host_id` 区分两台机器来源，同时保留完整日志文件。
12. 切换完成后云监控更新实际主机，并执行配置的外部回调。
13. 主机离线显示红色异常；mysql、rsync、SSH 采集失败等部分异常显示橙色提醒。
