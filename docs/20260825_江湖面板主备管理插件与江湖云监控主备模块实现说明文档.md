# 江湖面板主备管理插件与江湖云监控主备模块实现说明文档

**更新日期**：2026-08-25  
**适用范围**：江湖面板 `ha_manager` 主备管理插件、江湖云监控主备管理模块、服务器日报主备管理内容  
**江湖面板目录**：`/www/server/jh-panel`
**主备管理插件目录**：`/www/server/jh-panel/plugins/ha_manager`  
**主备管理插件运行目录**：`/www/server/ha_manager`  
**江湖云监控目录**：`/www/server/jh-monitor`

本文用于说明江湖面板主备管理插件、江湖云监控主备管理模块的数据存储和核心流程，重点覆盖：绑定主备关系、配置江湖云监控、自检、主备切换、上报江湖云监控、从江湖云监控拉取状态、主备异常检查、故障恢复补全、江湖云监控展示和日报汇总。

---

## 1. 总览

主备管理能力由江湖面板插件和江湖云监控共同完成：插件负责采集、切换、恢复、通知和上报；江湖云监控负责接收数据、展示状态、创建切换任务和生成日报汇总。

| 模块 | 位置 | 说明 |
| --- | --- | --- |
| 插件入口 | `/www/server/jh-panel/plugins/ha_manager/index.py` | 插件主要后端逻辑入口 |
| 切换执行器 | `/www/server/jh-panel/plugins/ha_manager/switch_runner.py` | 被上下线脚本调用，执行预上线、上线、下线阶段 |
| 插件页面 | `/www/server/jh-panel/plugins/ha_manager/index.html` | 主备管理插件页面 |
| 插件前端 | `/www/server/jh-panel/plugins/ha_manager/js/ha_manager.js` | 页面交互、弹窗、按钮、状态渲染 |

| 运行数据 | `/www/server/ha_manager/data` | 保存配置、状态、锁、通知周期等 |

## 3. 绑定主备关系

### 3.1 用途

绑定主备关系用于让当前机器知道对端是谁、如何连接对端、当前主备关系名称是什么。绑定后，插件才能采集对端状态、远程执行对端切换脚本、进行故障恢复协调。

### 3.2 入口

| 项目 | 内容 |
| --- | --- |
| 插件方法 | `save_binding` |
| 数据文件 | `/www/server/ha_manager/data/config.json` |

### 3.3 主要配置字段

| 字段 | 说明 |
| --- | --- |
| `pair_id` | 主备关系 ID |
| `pair_name` | 主备关系名称 |
| `host_id` | 本机唯一 ID |
| `host_name` | 本机名称 |
| `host_ip` | 本机 IP |
| `peer_host_id` | 对端主机 ID |
| `peer_public_ip` | 对端 SSH 地址 |
| `peer_ssh_port` | 对端 SSH 端口 |
| `peer_ssh_user` | 对端 SSH 用户 |
| `peer_public_key` | 对端公钥 |
| `bind_test_status` | SSH 绑定测试状态 |
| `role` | 本机当前角色，`master` 或 `standby` |
| `desired_role` | 本机期望角色 |

### 3.4 流程

```text
保存主备绑定
  │
  ├─ 写入对端 IP、SSH 端口、SSH 用户、公钥
  ├─ 如果没有 peer_host_id，则生成临时对端 ID
  ├─ 同步默认切换选项中的 remote_ip / remote_ssh_port
  ├─ 保存 config.json
  ├─ 生成本机 state.json
  └─ 尝试同步异常通知配置到对端
```

### 3.5 SSH 测试

| 项目 | 内容 |
| --- | --- |
| 插件方法 | `test_peer_ssh` |
| 核心动作 | SSH 到对端执行 `echo ok` |
| 成功结果 | `bind_test_status=success` |
| 失败结果 | `bind_test_status=failed` |

SSH 测试成功后，插件才能可靠执行：

- 采集对端状态。
- 拉取对端切换日志。
- 远程触发对端切换阶段。
- 故障恢复补全协调。
- 异常通知主备协同。

## 4. 配置云监控

### 4.1 用途

配置云监控后，插件会把主备状态、切换事件、异常通知事件上报到江湖云监控。江湖云监控也可以创建切换任务，由插件定时轮询后领取执行。

### 4.2 入口

| 项目 | 内容 |
| --- | --- |
| 插件方法 | `save_monitor` |
| 数据文件 | `/www/server/ha_manager/data/config.json` |

### 4.3 主要配置字段

| 字段 | 默认/示例 | 说明 |
| --- | --- | --- |
| `monitor_url` | `http://<ip>:10844` | 江湖云监控地址 |
| `monitor_disabled` | `false` | 是否禁用云监控 |
| `pair_name` | `生产面板主备` | 主备关系名称 |
| `poll_interval` | `10` | 轮询云监控间隔 |
| `report_interval` | `30` | 状态上报间隔 |
| `api_secret` | 自动生成 | 插件与江湖云监控通信签名密钥 |

### 4.4 流程

```text
保存云监控配置
  │
  ├─ 写入 monitor_url / pair_name
  ├─ 如果 monitor_url 为空，则禁用云监控
  └─ 如果 monitor_url 不为空
      │
      ▼
    注册到云监控
      │
      ├─ 采集本机状态
      ├─ SSH 尝试采集对端状态
      ├─ 组装 local_host / peer_host
      └─ 请求 /pub/ha_register_pair
```

注册成功后，插件保存江湖云监控返回的 `pair_id` 和 `api_secret`。

## 5. 自检状态

### 5.1 用途

自检用于判断当前机器是否符合当前角色的期望状态。例如当前是主机时，OpenResty 应运行、备份网站配置应启用；当前是备机时，OpenResty 应停止、恢复网站配置应启用。

### 5.2 入口

| 项目 | 内容 |
| --- | --- |
| 插件方法 | `get_state` |
| 状态文件 | `/www/server/ha_manager/data/state.json` |

### 5.3 自检项

自检项定义在 `index.py` 的 `HA_CHECK_DEFS`。

| 分组 | 检查项 |
| --- | --- |
| 计划任务 | 备份数据库、xtrabackup、xtrabackup-inc、备份网站配置、备份插件配置、证书续签、恢复网站配置、恢复插件配置 |
| SSH 同步 | `authorized_keys` 是否包含同步公钥 |
| rsync | rsyncd 同步任务、lsyncd 服务 |
| Web 服务 | OpenResty / nginx 状态 |
| 监控提醒 | 主从同步异常提醒、Rsync 状态异常提醒 |

### 5.4 主机角色期望

| 检查项 | 主机期望 | 备机期望 |
| --- | --- | --- |
| 备份数据库 | 停用 | 启用 |
| xtrabackup | 停用 | 启用 |
| 备份网站配置 | 启用 | 停用 |
| 备份插件配置 | 启用 | 停用 |
| 恢复网站配置 | 停用 | 启用 |
| 恢复插件配置 | 停用 | 启用 |
| OpenResty | 运行 | 停止 |
| lsyncd | 运行 | 停止 |
| rsyncd 同步任务 | 启用 | 停用 |
| 主从同步异常提醒 | 启用 | 停用 |
| Rsync 状态异常提醒 | 启用 | 停用 |

### 5.5 状态生成流程

```text
get_state
  │
  ├─ 读取 config.json
  ├─ SSH 采集对端状态
  ├─ _state() 生成本机状态快照
  ├─ 写入 state.json
  ├─ 读取 alert_state / alert_notifier_state
  ├─ 读取最近切换日志
  └─ 返回给插件页面
```

### 5.6 角色自动修复

插件生成状态时会尝试修复角色。

| 修复逻辑 | 说明 |
| --- | --- |
| `_repair_role_from_switch_status()` | 根据 `online_done` / `offline_done` 修正角色 |
| `_repair_role_from_script_state()` | 根据自检项通过数量推断当前更像主机还是备机 |

## 6. 主备切换

### 6.1 用途

主备切换用于将其中一台机器切换为主机，另一台机器切换为备机。插件支持本机执行和 SSH 远程触发对端执行。

### 6.2 切换阶段

| 阶段 | 说明 |
| --- | --- |
| `prepare_online` | 预上线，执行 checksum、文件同步、配置恢复等预备动作 |
| `offline` | 下线为备机，关闭主机相关任务和服务，启用备机相关任务 |
| `online` | 正式上线为主机，提升数据库、启用主机相关任务和服务 |

### 6.3 切换内容

主备切换不是只修改插件里的 `role` 字段，而是按目标角色调整数据库、计划任务、同步服务、Web 服务和监控提醒。切换完成后，插件会重新生成状态并上报江湖云监控。

| 阶段 | 主要内容 |
| --- | --- |
| `prepare_online` | 确认 MySQL 可用；按选项执行 xtrabackup 增量恢复、checksum 检查、文件同步、网站配置恢复、插件配置恢复 |
| `offline` | 将当前机器调整为备机：启用数据库备份和 xtrabackup 任务；停用网站/插件备份、lsyncd、证书续签；启用网站/插件恢复任务；停止 lsyncd、rsync 进程和 OpenResty；关闭主从同步、Rsync 状态、SSL 证书等提醒 |
| `online` | 将当前机器调整为主机：必要时提升 MySQL 为主；停用数据库备份和 xtrabackup 任务；启用网站/插件备份、lsyncd、证书续签；停用网站/插件恢复任务；启动 lsyncd 和 OpenResty；开启邮件、主从同步和 Rsync 状态提醒 |

预上线选项：

| 选项 | 说明 |
| --- | --- |
| `run_xtrabackup_inc_restore` | 是否先执行 xtrabackup 增量恢复 |
| `run_checksum` | 是否检查主备 MySQL checksum |
| `sync_files` | 是否从对端同步 `/www/wwwroot`、`/www/wwwstorage` 等文件目录 |
| `sync_file_dirs` | 文件同步目录，默认 `/www/wwwroot,/www/wwwstorage` |
| `sync_ignore_dirs` | 文件同步排除目录，默认 `.git,node_modules,logs,run` |
| `restore_site_setting` | 是否恢复网站配置 |
| `restore_plugin_setting` | 是否恢复插件配置 |

### 6.4 完整切换流程

目标主机是本机时：

```text
本机执行 prepare_online
  │
  ▼
SSH 触发对端执行 offline
  │
  ▼
本机执行 online
  │
  ▼
等待 3 秒
  │
  ▼
本机上报状态
  │
  ▼
SSH 触发对端上报状态
```

目标主机是对端时：

```text
SSH 触发对端执行 prepare_online
  │
  ▼
本机执行 offline
  │
  ▼
SSH 触发对端执行 online
  │
  ▼
等待 3 秒
  │
  ▼
本机上报状态
  │
  ▼
SSH 触发对端上报状态
```

### 6.5 执行模式判断

核心函数为 `_switch_execution_mode()`。

| 模式 | 说明 |
| --- | --- |
| `full_switch` | 本机和对端都可执行，允许完整双边切换 |
| `local_failover` | 对端不可达，但目标是本机升主，允许故障升主 |
| `blocked_remote_unreachable` | 目标是对端但对端不可达，不允许切换 |

判断内容：

- 是否绑定对端 IP。
- SSH 是否验证通过。
- 对端插件是否存在并可执行。
- 对端配置是否完整。
- 对端是否存在正在执行的切换锁。

## 7. 上报江湖云监控

### 7.1 用途

插件定时把本机和对端状态上报给江湖云监控，江湖云监控据此展示主备关系、主机列表、自检状态、切换状态和异常状态。

### 7.2 入口

| 项目 | 内容 |
| --- | --- |
| 定时任务 | `report_state` |
| 执行方式 | 江湖面板 `task.py` 进程根据插件 `info.json` 的配置定时执行 |
| 周期 | 30 秒 |
| 请求接口 | `/pub/ha_report_state` |
| 日志 | `/www/server/ha_manager/logs/report_state.log` |

### 7.3 流程

```text
report_state
  │
  ├─ 读取 config.json
  ├─ 如果 monitor_url 为空或 monitor_disabled=true，则跳过
  ├─ 生成 report_batch_id
  ├─ 调用 _state() 生成本机状态并写入 state.json
  ├─ 通过 SSH 调用对端 get_local_state 采集对端状态
  ├─ 对端可达时，拉取对端 switch/<run_id>.log 并上报新增日志行
  ├─ 组装 hosts 列表
  ├─ 如果切换已完成且能识别实际主机，同步 desired_master_host_id
  └─ POST /pub/ha_report_state
```

### 7.4 上报主机类型

| 类型 | `collect_method` | `site_scope` | 说明 |
| --- | --- | --- | --- |
| 本机状态 | `local` | `local` | 当前插件直接采集的本机状态 |
| 对端状态 | `ssh_peer` | 默认 `remote` | 当前插件通过 SSH 采集到的对端状态；如果对端也直接上报到同一个江湖云监控，江湖云监控侧可按直接上报数据展示为本机房 |
| 对端不可达占位 | `ssh_peer` | `remote` | SSH 失败时生成的对端失败状态 |

## 8. 从江湖云监控拉取状态和任务

### 8.1 用途

插件通过轮询江湖云监控获取期望主机和切换任务。江湖云监控不会主动连接插件，任务执行依赖插件定时拉取。

### 8.2 入口

| 项目 | 内容 |
| --- | --- |
| 定时任务 | `poll_monitor` |
| 执行方式 | 江湖面板 `task.py` 进程根据插件 `info.json` 的配置定时执行 |
| 周期 | 10 秒 |
| 请求接口 | `/pub/ha_pull_desired_state` |
| 日志 | `/www/server/ha_manager/logs/poll_monitor.log` |

### 8.3 流程

```text
poll_monitor
  │
  ├─ 读取 config.json
  ├─ 如果 monitor_url 为空或 monitor_disabled=true，则跳过
  ├─ 向江湖云监控提交 pair_id / host_id
  ├─ 拉取 desired_master_host_id 和 switch_run
  ├─ 根据 desired_master_host_id 更新本机 desired_role
  ├─ 如果返回 switch_run，则同步 switch_run_id / switch_status / log_path
  └─ 调用 _start_cloud_switch_phase() 判断是否领取切换阶段，确认领取后执行切换流程
```

## 9. 主备异常检查

### 9.1 用途

主备异常检查由插件自己完成，用于发现主备关系异常，并通过江湖面板通知能力发送邮件/通知。江湖云监控只接收通知事件用于展示，不负责发送通知。

### 9.2 入口

| 项目 | 内容 |
| --- | --- |
| 定时任务 | `alert_check` |
| 执行方式 | 江湖面板 `task.py` 进程根据插件 `info.json` 的配置定时执行 |
| 周期 | 30 秒 |
| 日志 | `/www/server/ha_manager/logs/alert_check.log` |

### 9.3 配置字段

配置存储在 `/www/server/ha_manager/data/config.json`。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `alert_enabled` | `false` | 是否启用异常通知 |
| `primary_notifier_host_id` | 自动计算 | 主通知方 |
| `alert_takeover_fail_count` | `3` | 主通知方连续不可达几次后备用接管 |
| `alert_takeover_recover_count` | `2` | 主通知方连续恢复几次后退出接管 |
| `alert_recovery_notify` | `true` | 异常恢复后是否通知 |
| `alert_key_health_check_enabled` | `false` | 是否启用关键健康项检测 |

### 9.4 异常来源

| 异常类型 | 说明 |
| --- | --- |
| `host_unreachable` | 对端不可达 |
| `double_master` | 双主 |
| `no_master` | 双备或无主 |
| `degraded_master` | 故障升主后的降级运行 |
| `recovery_guard` | 恢复保护，待恢复为备机 |
| `switch_stuck` | 切换锁残留 |
| `health_failed` | 自检项失败 |
| `health_warning` | 健康状态提醒 |

### 9.5 检测流程

```text
alert_check
  │
  ├─ 读取 config.json
  ├─ alert_enabled=false 时跳过
  ├─ 采集本机状态和对端状态
  ├─ 读取 failover_state 和 switch.lock 状态
  ├─ 计算当前异常集合 active_alerts
  ├─ 判断本机是否是当前通知方
  ├─ 首次出现异常时发送一次异常通知
  ├─ 异常持续存在时更新状态但不重复发送
  └─ 全部异常恢复后发送一次恢复通知并清空异常状态
```

### 9.6 通知周期

```text
无异常 -> 出现异常
  => 发送一次异常通知

异常仍存在
  => 不重复发送

异常全部恢复
  => 发送一次恢复通知，并清空异常状态

恢复后再次异常
  => 进入新的异常周期，再发送一次异常通知
```

不同异常会合并成一个异常周期。已经处于异常周期时，即使出现新的异常，也不会重复通知。

### 9.7 通知方判断

```text
如果本机是 primary_notifier_host_id
  => 本机发送通知

如果本机不是主通知方
  ├─ 主通知方可达
  │   └─ 本机不发送
  └─ 主通知方连续不可达达到阈值
      └─ 本机作为备用方接管通知
```

同一个异常周期确定 `notification_owner_host_id` 后，恢复通知也由同一个通知方发送。

## 10. 故障恢复补全

### 10.1 用途

当一台主机故障停机，另一台机器临时故障升主后，故障机器恢复时需要自动或半自动恢复为备机，避免双主风险。

### 11.6 江湖云监控切换任务流转

江湖云监控不直接 SSH 到主机执行切换脚本，而是创建切换任务，等待主备管理插件通过 `poll_monitor` 领取执行。

```text
江湖云监控页面点击预上线/正式上线
  │
  ├─ /ha/request_switch 创建 ha_switch_run
  ├─ 更新 ha_pair.current_switch_run_id 和 desired_master_host_id
  ├─ 插件通过 /pub/ha_pull_desired_state 拉取任务
  ├─ 江湖云监控根据阶段目标判断 execute_phase / execute_method / execute_target_host_id
  ├─ 插件领取任务并执行本机或 SSH 对端阶段
  ├─ 插件上报 /pub/ha_report_switch_event 或 /pub/ha_ack_switch_phase
  └─ 江湖云监控推进 ha_switch_run 状态，并更新 ha_pair 状态
```

阶段状态推进规则：

| 阶段 | 成功后状态 | 说明 |
| --- | --- | --- |
| `prepare_online` | `prepare_success` | 预上线完成，等待操作员执行正式上线 |
| `offline` | `pending_online` | 旧主机下线完成，等待目标主机领取上线阶段 |
| `online` | `success` | 正式上线完成，更新实际主机和期望主机，清空当前切换任务 |
| 任意阶段失败 | `waiting_retry` | 保存失败原因，等待重试或取消 |

### 11.7 状态计算与展示

江湖云监控列表和详情展示不是直接原样显示数据库字段，而是由 `ha_api._normalizePair()` 统一整理。核心逻辑包括：

| 逻辑 | 说明 |
| --- | --- |
| 主机状态合并 | 按最新 `report_batch_id`、`host_id`、`host_ip`、`collect_method` 合并展示状态，优先展示更可信的 `local` 上报 |
| 本机房判断 | `collect_method=local` 的主机视为直接上报；`ssh_peer` 默认视为远端采集，除非同一江湖云监控也收到了该主机的 `local` 上报 |
| 关系状态计算 | 根据主机角色、上报时间、采集状态、自检结果、故障恢复状态、期望主机和实际主机是否一致计算 `normal`、`warning`、`danger`、`switching` |
| 异常提示 | 双主、双备/无主、主机离线、主插件失联、SSH 采集异常、自检异常、降级运行、恢复保护都会进入状态文案 |
| 日志展示 | 详情页“日志”展示异常通知事件和切换任务列表；点击查看后读取 `ha_switch/<月份>/<run_id>.log` |

## 12. 双江湖云监控主备数据同步

### 12.1 用途

当两个机房各自部署一套江湖云监控时，主备管理插件仍然只连接本机房配置的江湖云监控。江湖云监控之间通过同步事件机制互相拉取主备数据，使两边都能看到同一组主备关系的最新状态，并支持在一边创建切换任务、由另一边可用插件领取执行。

典型场景：A 机房业务主机停机，但 A 江湖云监控仍可访问；B 机房插件还能上报 B 本机状态和 A 对端状态。同步开启后，A 江湖云监控可以通过 B 江湖云监控获得最新主备状态，也可以把切换任务同步给 B 江湖云监控，由 B 插件执行。

### 12.2 数据存储

同步数据仍写入江湖云监控本地 SQLite 数据库 `/www/server/jh-monitor/data/default.db`。页面和日报继续读取本地 `ha_*` 表，不直接远程查询对端江湖云监控。

| 表 | 说明 |
| --- | --- |
| `ha_monitor_identity` | 当前江湖云监控实例身份，保存稳定的 `monitor_id` 和 `monitor_name` |
| `ha_sync_config` | 云监控同步配置列表，保存对端地址、对端 ID、同步密钥、启停状态、最近同步时间和错误 |
| `ha_sync_event` | 本机产生的待同步业务事件，通过 `sync_type` 区分数据域，当前为 `ha_management` |
| `ha_sync_cursor` | 每条同步配置、每种同步类型的拉取游标 |
| `ha_sync_applied` | 已应用事件记录，用于幂等去重 |
| `ha_sync_nonce` | 同步接口签名 nonce，防止重放 |

主备业务表新增了同步相关字段：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `ha_pair` | `source_monitor_id`、`sync_update_at` | 标识关系数据来源和同步应用时间 |
| `ha_host_state` | `source_monitor_id`、`sync_update_at` | 标识主机状态来源和同步应用时间 |
| `ha_switch_run` | `origin_monitor_id`、`execution_monitor_id`、`claimed_by_host_id`、`claim_token`、`claim_expire_at`、`dispatchable`、`dispatch_reason`、`source_monitor_id`、`sync_update_at` | 标识切换任务创建方、执行方、领取状态、是否可下发和同步来源 |

同步日志写入：

```text
/www/server/jh-monitor/logs/ha_sync/<YYYY-MM>.log
```

### 12.3 配置入口

配置入口在江湖云监控“设置”页面的“云监控同步”区域。

| 配置项 | 说明 |
| --- | --- |
| 同步名称 | 便于识别对端机房或用途 |
| 同步江湖云监控 | 对端江湖云监控地址 |
| 同步类型 | 当前只支持“同步主备相关数据”，即 `ha_management` |
| 同步密钥 | 两套江湖云监控之间 HTTP 同步接口的共享密钥 |
| 启用状态 | 启用后才会被后台同步任务处理 |

支持添加、编辑、删除、启用/停用、测试连接和立即同步。测试连接会请求对端握手接口，成功后保存对端 `monitor_id` 和 `monitor_name`。

### 12.4 同步接口

江湖云监控之间通过 `/pub/ha_monitor_sync_*` 接口通信。

| 接口 | 处理函数 | 说明 |
| --- | --- | --- |
| `/pub/ha_monitor_sync_handshake` | `publicMonitorSyncHandshake()` | 校验同步密钥，交换两边 `monitor_id`、名称和同步版本 |
| `/pub/ha_monitor_sync_pull` | `publicMonitorSyncPull()` | 按 `sync_type` 和 `after_seq` 拉取对端新增同步事件 |
| `/pub/ha_monitor_sync_ack` | `publicMonitorSyncAck()` | 确认本地已应用到哪个游标 |

同步接口使用独立签名头：

| Header | 说明 |
| --- | --- |
| `X-JHM-Timestamp` | 请求时间戳 |
| `X-JHM-Nonce` | 一次性随机值 |
| `X-JHM-Body-Hash` | 请求体 SHA256 |
| `X-JHM-Signature` | 使用同步密钥生成的 HMAC-SHA256 签名 |

### 12.5 定时同步流程

同步由江湖云监控 `task.py` 中的 `haMonitorSyncTask()` 定时执行，周期为 15 秒。

```text
haMonitorSyncTask
  │
  ├─ 查询 ha_sync_config 中 enabled=1 的同步配置
  ├─ 读取 ha_sync_cursor.last_seq
  ├─ 请求对端 /pub/ha_monitor_sync_pull
  ├─ 按 event_type 应用事件到本地 ha_* 表
  ├─ 写入 ha_sync_applied，避免重复应用
  ├─ 全部成功后推进 ha_sync_cursor
  ├─ 尝试请求对端 /pub/ha_monitor_sync_ack
  └─ 更新 ha_sync_config.last_sync_at / last_error / status
```

如果某一批事件中有事件应用失败，当前批次不会推进游标，下次仍从原游标继续拉取，避免跳过未成功应用的数据。

### 12.6 同步事件来源

江湖云监控在本地业务数据变化时追加 `ha_sync_event`。

| 事件类型 | 触发来源 | 同步内容 |
| --- | --- | --- |
| `ha_pair` | 插件注册、状态上报、创建切换任务 | 主备关系、期望主机、实际主机、整体状态 |
| `ha_host_state` | `/pub/ha_report_state` | 同步当前江湖云监控收到的完整主备状态，包括 `collect_method=local` 和 `collect_method=ssh_peer` 的状态、自检明细、采集状态、切换状态 |
| `ha_switch_run` | `/ha/request_switch`、阶段推进 | 切换任务、阶段、执行方、领取状态、最终状态 |
| `ha_switch_event` | `/pub/ha_report_switch_event` | 切换日志行和阶段事件 |
| `ha_alert_event` | `/pub/ha_report_alert_event` | 异常通知和恢复通知事件 |

### 12.7 状态合并规则

同步过来的 `ha_host_state` 按 `pair_id + host_id` 合并。

| 场景 | 规则 |
| --- | --- |
| 新状态的 `last_report_at` 更新 | 覆盖同一主机状态 |
| 时间相同但来源不同 | 优先保留 `collect_method=local` |
| 同步过来的是旧的失败占位 | 不覆盖本地更新鲜的成功状态 |
| 一次上报包含两台主机 | 保留 `report_batch_id`，让页面继续按同一批数据合并展示 |
| 当前主机已被本地上报确认为本机房 | 后续对端同步数据可以更新状态，但不能把 `site_scope=local` 改成远端 |

主机状态同步边界：

| 状态来源 | 是否导出同步事件 | 说明 |
| --- | --- | --- |
| `collect_method=local` | 是 | 表示插件直接采集的本机状态 |
| `collect_method=ssh_peer` | 是 | 表示插件通过 SSH 看到的对端状态；同步到另一套江湖云监控后，可在对端主机离线或未及时上报时补足状态 |
| 对端不可达占位 | 是 | 表示当前插件采集到的最新不可达结果；展示时按时间、采集状态和来源合并，不覆盖本地更新鲜的成功状态 |

页面展示会合并当前江湖云监控本地数据和对端同步数据：当前江湖云监控直接收到的 `local`、`ssh_peer` 状态都显示为“本地上报”；对端江湖云监控同步来的 `local`、`ssh_peer` 状态显示为“江湖云监控同步”。这个判断以 `source_monitor_id` 是否等于当前江湖云监控 `monitor_id` 为准，不以 `collect_method` 为准。

### 12.8 跨江湖云监控切换任务

切换任务通过 `origin_monitor_id` 和 `execution_monitor_id` 区分创建方和执行方。

```text
A 江湖云监控创建切换任务
  │
  ├─ origin_monitor_id = A
  └─ execution_monitor_id = B（如果 A 当前没有可执行插件）
      │
      ▼
任务同步到 B 江湖云监控
      │
      ▼
B 插件 poll_monitor 从 B 江湖云监控领取任务
      │
      ▼
B 插件按原有 local / ssh_peer 主备切换流程执行
      │
      ▼
B 江湖云监控接收日志和阶段结果
      │
      ▼
日志、ack、最终状态同步回 A 江湖云监控
```

执行保护规则：

| 规则 | 说明 |
| --- | --- |
| 只有执行方下发 | `/pub/ha_pull_desired_state` 只有在 `execution_monitor_id` 等于当前江湖云监控 `monitor_id` 时才返回 `execute_phase` |
| 单阶段领取 | 已有 `claimed_by_host_id` 且领取未过期时，不再下发给其他主机 |
| 同关系冲突 | 同一个 `pair_id` 已有未完成任务时，同步过来的新任务标记为 `conflict` 或不可下发 |
| 日志去重 | 切换日志用 `event_id` 或 `switch_run_id + origin_host_id + seq` 去重 |

## 13. 服务器日报中的主备管理

### 13.1 用途

服务器日报会汇总江湖云监控中的主备关系状态，展示主备管理概览、异常主备摘要和提醒主备摘要。日报只读取江湖云监控数据库中的主备状态，不直接连接江湖面板插件。

### 13.2 生成逻辑

日报生成逻辑在 `/www/server/jh-monitor/scripts/report_analyser.py`。生成全局概览报告时，如果 `ha_enabled=true`，会调用 `_build_ha_management_overview()` 读取 `ha_pair` 和 `ha_host_state`，并复用 `ha_api._normalizePair()` 的状态判断逻辑。

```text
build_overview_report
  │
  ├─ 生成主机概览、异常主机摘要、提醒主机摘要
  ├─ 生成监控任务概览
  ├─ 如果 ha_enabled=true，生成 ha_overview
  ├─ 将主备异常/提醒写入 overview_summary_messages
  ├─ 计算邮件标题中的异常/提醒数量
  └─ 渲染 route/templates/report/host_overview_report.html
```


### 13.3 日报展示内容

| 展示区域 | 说明 |
| --- | --- |
| 概要信息 | 只有存在异常/提醒主备时，才在概要中显示“主备管理：共 N 个，正常 N 个，异常/提醒 N 个” |
| 主备管理概览 | 显示主备关系总数、正常主备数量、异常/提醒主备数量 |
| 异常主备摘要 | 展示 `danger` 状态的主备关系，包含关系名称、`pair_id`、异常原因、主机信息和最近上报时间 |
| 提醒主备摘要 | 展示非 `danger` 但非正常的主备关系，例如 `warning`、`switching`、`unknown` |

模板位置：

```text
/www/server/jh-monitor/route/templates/report/host_overview_report.html
```

## 14. 排障速查

| 问题 | 优先查看 |
| --- | --- |
| 插件定时任务有没有执行 | `/www/server/jh-panel/logs/plugin_scheduled_tasks.log` |
| 状态有没有上报江湖云监控 | `/www/server/ha_manager/logs/report_state.log` |
| 和江湖云监控交互是否失败 | `/www/server/logs/ha_manager_cloud.log` |
| 江湖云监控任务有没有被插件领取 | `/www/server/ha_manager/logs/poll_monitor.log` |
| 江湖云监控任务有没有启动执行 | `/www/server/ha_manager/logs/cloud_task_launcher.log` |
| 切换脚本具体执行到哪一步 | `/www/server/ha_manager/logs/switch/<run_id>.log` |
| 对端切换日志有没有被拉取 | `/www/server/ha_manager/logs/peer/<peer_host_id>/<run_id>.log` |
| 故障恢复为什么没触发 | `/www/server/ha_manager/logs/recover_check.log` |
| 两套江湖云监控是否同步成功 | `/www/server/jh-monitor/logs/ha_sync/<YYYY-MM>.log` |
| 同步配置最近错误 | 江湖云监控“设置 -> 云监控同步”列表，或 `ha_sync_config.last_error` |
| 同步游标是否推进 | `ha_sync_cursor.last_seq` |
| 同步任务是否重复应用 | `ha_sync_applied.event_id` |
| 跨监控切换任务由谁执行 | `ha_switch_run.origin_monitor_id` / `ha_switch_run.execution_monitor_id` |
| 异常通知为什么没发 | `/www/server/ha_manager/logs/alert_check.log` |
| 当前插件配置 | `/www/server/ha_manager/data/config.json` |
| 当前插件状态 | `/www/server/ha_manager/data/state.json` |
| 当前异常通知周期 | `/www/server/ha_manager/data/alert_state.json` |
| 当前故障恢复状态 | `/www/server/ha_manager/data/failover_state.json` |
| 江湖云监控主备数据 | `/www/server/jh-monitor/data/default.db` 中的 `ha_*` 表 |
| 江湖云监控切换任务日志 | `/www/server/jh-monitor/logs/ha_switch/<YYYY-MM>/<switch_run_id>.log` |
| 江湖云监控页面接口 | `/www/server/jh-monitor/class/core/ha_api.py` |
| 插件调用江湖云监控公开接口 | `/www/server/jh-monitor/class/core/pub_api.py` |
| 日报是否展示主备管理 | `/www/server/jh-monitor/data/report_config.json` 中的 `ha_enabled` |
| 日报主备概览生成逻辑 | `/www/server/jh-monitor/scripts/report_analyser.py` 的 `_build_ha_management_overview()` |
