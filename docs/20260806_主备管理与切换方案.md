# 主备管理与切换方案

## 目标

- 江湖云监控统一展示主备服务器状态，包括当前哪个为主、哪个为备，以及主备服务器的自检状态，如 MySQL 主从、rsyncd、OpenResty、计划任务等。
- 江湖云监控在主备状态异常时进行提示，支持正常、提醒、异常、切换中 4 类状态展示。
- 江湖云监控支持手动切换服务器主备状态，切换过程可追踪、可重试、可回调外部系统。

## 方案简介

### 1. 江湖面板新增 `ha_manager` 主备管理插件

- 插件安装在两台江湖面板服务器上，用于绑定两个服务器的主备关系。
- 绑定时输入对方公网 IP、SSH 端口、SSH 用户和对方公钥，测试 SSH 连接后保存。
- 插件配置云监控地址和主备关系名称；云监控地址默认空，为空时不上传状态。
- 插件周期性采集本机状态，并通过 SSH 获取对端状态，统一上报到当前机房的云监控。
- 插件支持手动发起主备切换，用户可选择要切换的主机，并配置切换选项。

### 2. 江湖云监控新增主备管理模块

- 云监控展示插件上报的主备关系，不提供手动添加主备关系入口。
- 主备关系按业务主体划分，例如 `江湖平台`、`江湖演示`、`Dev02`、`MD 旋风`。
- 主机名称按 `业务主体@机房` 展示，例如 `江湖平台@Mega`、`江湖平台@Polaris`。
- 列表展示主备关系、主机、状态、最近上报、操作。
- 详情弹框展示概览、主机列表、自检状态、切换日志。

## 主备状态展示

| 状态 | 说明 | 展示规则 |
|---|---|---|
| 正常 | 实际主备状态与期望状态一致，关键自检正常 | 绿色 |
| 提醒 | 部分状态异常，但主业务仍可运行，如备用机离线、MySQL 延迟、rsync 异常 | 橙色 |
| 异常 | 主机离线、双主、切换失败等需要重点处理的问题 | 红色 |
| 切换中 | 当前存在下线、上线、验证等切换流程 | 蓝色或 loading 标识 |

状态列直接展示 4 类状态和具体状态描述；鼠标移入状态时展示提醒内容、当前状态、期望状态、正在执行的操作、实际主机和期望主机。

## 自检状态

自检状态按主机分别展示，每台机器都展示当前角色下的期望状态和实际状态。

| 分组 | 检查项示例 |
|---|---|
| 计划任务 | 备份数据库、xtrabackup、恢复网站配置、恢复插件配置、lsyncd 实时同步、证书续签任务 |
| 监控提醒 | 主从同步异常提醒、Rsync 状态异常提醒 |
| SSH 同步 | authorized_keys 同步公钥、对端 SSH 连接 |
| rsync | rsyncd 任务、残留 rsync 进程 |
| Web 服务 | OpenResty |
| 数据库 | MySQL 主从状态 |

示例规则：

```text
1. 主机作为“主”时，MySQL 应为“无主从配置（作为主）”。
2. 主机作为“备”时，MySQL 应为“作为从库（复制链路正常）”。
3. 切换过程中，在自检状态的主机卡片上显示“切换中”loading 标识。
4. 未绑定主备关系时，对端状态整体显示为灰色。
```

## 手动切换流程

云监控和插件都支持手动切换入口。

```text
1. 用户点击“切换主备”
2. 选择要切换的目标主机
3. 配置切换选项
4. 确认后创建切换任务
5. 云监控更新 SQLite 中的期望主备状态
6. ha_manager 插件轮询云监控 API，获取期望状态
7. 插件执行上下线脚本流程
8. 插件上报切换状态和日志
9. 切换完成后立即上报实际主备状态
10. 云监控根据配置回调外部地址
```

切换流程需要包含以下脚本的完整流程：

```text
/www/server/jh-panel/scripts/os_tool/vm/default/switch__generate_offline.sh
/www/server/jh-panel/scripts/os_tool/vm/default/switch__generate_online.sh
```

## 切换选项

| 选项 | 默认 | 说明 |
|---|---|---|
| 同步文件 | 勾选 | 勾选后显示同步目录和忽略目录配置 |
| 检查 checksum | 勾选 | 切换前进行文件校验 |
| 允许忽略 checksum 差异 | 不勾选 | 允许在校验不一致时继续流程 |
| 恢复网站配置 | 不勾选 | 上线时恢复网站配置 |
| 面板插件配置 | 不勾选 | 上线时恢复面板插件配置 |
| 执行增量恢复 | 不勾选 | 上线时执行 xtrabackup 增量恢复 |

`提升数据库为主` 不作为可选项展示，作为切换为主的固定流程执行。

## 状态与日志上报

- 切换状态和日志统一通过 API 上报。
- 云监控保存每次切换的日志文件。
- SQLite 只保存当前状态和日志文件路径。
- 日志保存目录：

```text
/www/server/jh-monitor/logs/ha_switch/
```

上报数据需要区分以下字段：

| 字段 | 说明 |
|---|---|
| `pair_name` | 主备关系名称 |
| `origin_host_id` | 状态或日志来源主机 |
| `report_host_id` | 实际上报到云监控的主机 |
| `collect_method` | 采集方式，`local` 或 `ssh_peer` |
| `collect_status` | 采集状态 |
| `actual_role` | 实际角色，主或备 |
| `desired_role` | 期望角色，主或备 |
| `switch_run_id` | 本次切换任务 ID |
| `log_path` | 云监控侧日志文件路径 |

## 双机房采集方式

- Mega 和 Polaris 两个机房各自部署一套云监控。
- 云监控不直接跨机房 SSH 采集。
- 插件负责采集本机状态，并通过 SSH 获取对端状态。
- 插件将本机和对端的主备状态、自检状态、切换状态和日志统一上报到当前机房云监控。
- SSH 采集失败只表示对端采集异常，不直接等同于对端主机离线。

## 回调机制

- 云监控在主备实际状态变化后，回调配置的外部地址。
- 回调用于通知江湖数据同步等系统切换数据库或同步任务状态。
- 回调应在切换完成并确认实际主备状态后触发。

## 存储约定

| 存储位置 | 内容 |
|---|---|
| SQLite | 主备关系状态、期望状态、实际状态、日志路径、最近上报时间 |
| `/www/server/jh-monitor/logs/ha_switch/` | 每次切换的完整日志文件 |

## 第一阶段范围

- 支持手动切换，不做自动故障切换。
- 云监控只更新期望状态，实际切换由插件轮询后执行。
- 插件和云监控界面先完成主备展示、自检展示、切换入口和日志展示。
- 后续再接入真实 API、SQLite 存储、脚本执行器、回调和重试机制。
